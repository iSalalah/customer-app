# 07 — Security Threat Summary

Ordered by residual risk after the controls below are in place.

| # | Threat | Vector | Controls | Residual |
|---|---|---|---|---|
| T1 | **Next citizen reads the previous citizen's data** (the defining kiosk risk) | Someone walks up 40 s after the previous user left | 2-minute **server-side** idle expiry; absolute 30-minute cap; `Cache-Control: no-store, no-cache, must-revalidate, private` + `Pragma: no-cache` on every authenticated response; SPA purges React state, clears the TanStack Query cache, `history.replaceState` to `/` and installs a `popstate` trap; nothing sensitive in `localStorage`/`sessionStorage`; explicit **End session** button on every authenticated screen | Low. A physically attached debugger on the kiosk is out of scope (kiosk OS hardening). |
| T2 | **OTP brute force / SMS pumping** | Scripted `otp/verify` or repeated `otp/request` | 6 digits from `crypto.randomInt`; HMAC-SHA256 storage under `OTP_PEPPER` (never plaintext); `timingSafeEqual` compare; 5-minute TTL; max 5 attempts then challenge invalidated; 60 s resend cooldown; 3/hour/phone + 10/hour/IP + 5/15 min/IP; issuing a new challenge invalidates all prior active ones; codes never logged, never returned outside `NODE_ENV=development` | Low. SIM-swap remains an accepted risk of phone-based auth. |
| T3 | **Citizen enumeration / outcome mining via public tracking** | Iterating `DHO-2026-XXXXXX` | 6-char cryptographic suffix over a 32-symbol alphabet (~1.07e9 space); response carries **only** reference, coarse status, two dates; `APPROVED` and `REJECTED` both render `CLOSED`; 10 requests / 5 min / IP; unknown reference and rate-limited reference are indistinguishable in shape | Low–medium. A distributed scraper can confirm *existence*; it learns nothing about who or what. |
| T4 | **Horizontal privilege escalation between staff scopes** | Staff guesses another department's `requestId` | Scope re-derived from the loaded row in the service layer, not from any client value; list filters intersect with scope; assignment validated against the assignee's own `departmentId`/`sectionId`; out-of-scope reads return `404`, not `403`, so ids are not confirmed | Low. Covered by `rbac.scope.test.js`. |
| T5 | **Internal notes leaking to a citizen** | Serialiser reuse between staff and citizen paths | Separate query (`visibility: CITIZEN_VISIBLE` in the `WHERE`, not filtered afterwards) and a separate field-allowlist serialiser; a dedicated test asserts an internal note never appears in a citizen payload | Low. |
| T6 | **Malicious upload** (webshell, polyglot, zip bomb, MIME spoof) | Multipart upload | Allowlist PDF/JPEG/PNG by **magic bytes** (`file-type`) *and* declared MIME; browser filename never touches the path — storage key is `yyyy/mm/<uuid>.<ext>`; 10 MB/file, 5 files/request, 25 MB total body; files stored outside any web root with no static handler; downloads go through an authorising controller with `Content-Disposition: attachment` and `X-Content-Type-Options: nosniff`; scanner adapter with quarantine (`scanStatus`) | Low–medium in dev where the scanner is a no-op. Production must set `MALWARE_SCAN_ENABLED=true`. |
| T7 | **CSRF on cookie-authenticated mutations** | Attacker page posts to the API | `SameSite=Strict` (`Lax` for the admin refresh cookie path); double-submit `X-CSRF-Token` vs `dm.csrf` cookie compared with `timingSafeEqual`; strict CORS allowlist with `credentials: true` and **no** wildcard; `Origin` checked on state-changing verbs | Low. |
| T8 | **Session fixation / token theft** | XSS or replay | Tokens are opaque 256-bit values in `HttpOnly` cookies, never readable by JS and never in `localStorage`; only a SHA-256 hash is stored server-side; the session id rotates on OTP verification and on every staff refresh; refresh-token reuse revokes the whole family; helmet CSP forbids inline script | Low. |
| T9 | **Staff credential stuffing** | Leaked password lists | Argon2id (m=19456, t=2, p=1); 5 failures → 15-minute lockout; per-IP login limiter (10/15 min); uniform `INVALID_CREDENTIALS` and a constant-time dummy verify for unknown usernames so timing does not confirm existence; every attempt written to `AuthenticationAudit` | Medium — MFA for staff is **not** in scope for v1 and is the top recommended follow-up. |
| T10 | **Mass assignment / client-controlled routing** | Extra fields in the JSON body | Zod `.strict()` on every body; the service builds Prisma payloads field-by-field from validated values; `departmentId`/`sectionId`/`status`/`assignedTo`/`referenceNumber` are **never** read from a citizen request body — routing comes from the `MunicipalService` row | Low. |
| T11 | **Duplicate submissions** (double-tap on a touchscreen) | Impatient tapping / retry | `Idempotency-Key` header, `@@unique([citizenId, idempotencyKey])`, plus a 24 h Redis replay cache; the SPA generates the key once per wizard session and disables the submit control on the first tap | Low. |
| T12 | **Information leakage through errors** | Prisma/SQL/stack in a response | Central error handler maps known errors to safe codes; unknown errors become `INTERNAL_ERROR`; the detail is logged once against the correlation id; pino redaction covers `password`, `code`, `otp`, `token`, `authorization`, `cookie`, `passwordHash`, `civilId*` | Low. |
| T13 | **DoS via large bodies / slow uploads** | Oversized multipart | `express.json({ limit: '100kb' })`, multipart caps in Multer, global limiter 300/15 min/IP, upload limiter 20/hour/citizen, `server.headersTimeout`/`requestTimeout` set | Medium — a network-edge WAF/CDN is still assumed in production. |
| T14 | **Secrets in the repository** | Careless commit | No secret literal anywhere in source; startup **fails closed** if any required variable is missing or is a known dev placeholder while `NODE_ENV=production`; `.env` is git-ignored and only `.env.example` is committed | Low. |
| T15 | **HTTP parameter pollution** | `?status=PENDING&status=APPROVED` | Custom `hpp` middleware collapses duplicated query keys to the last value before validation; Zod then rejects unexpected shapes | Low. |

## Explicitly out of scope for v1

- Staff MFA (recommended next, see T9).
- Field-level encryption beyond `civilId`.
- Anti-automation on the public tracking endpoint beyond IP rate limiting (no CAPTCHA —
  a CAPTCHA is inaccessible on a touch kiosk).
- Physical kiosk hardening (BIOS, USB ports, browser kiosk mode) — an operations
  responsibility documented in `docs/08-deployment.md`.
